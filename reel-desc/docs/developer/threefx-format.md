# .3fx Format (ElementFX)

The `.3fx` format is the elemental effects playback track — a sparse, run-length encoded timeline of wind, water, and heat intensities.

## Format

Newline-delimited JSON. One object per effect **change**, sorted by timestamp.

```json
{"t": 0.0,   "wind": 0, "water": 0, "heat_ambient": 0, "heat_radiant": 0}
{"t": 312.5, "wind": 2, "water": 0, "heat_ambient": 1, "heat_radiant": 3}
{"t": 318.0, "wind": 3, "water": 0, "heat_ambient": 1, "heat_radiant": 0}
{"t": 401.2, "wind": 0, "water": 2, "heat_ambient": 0, "heat_radiant": 0}
```

## Fields

| Field | Type | Description |
|---|---|---|
| `t` | float | Timestamp in seconds |
| `wind` | int 0–3 | Wind intensity |
| `water` | int 0–3 | Water intensity |
| `heat_ambient` | int 0–3 | Sustained heat intensity |
| `heat_radiant` | int 0–3 | Burst heat intensity |

## Intensity scale

| Value | Meaning |
|---|---|
| 0 | None |
| 1 | Subtle |
| 2 | Moderate |
| 3 | Intense |

## Playback

The `.3fx` file is a `timestamp → effect` lookup table. The playback engine binary-searches for the entry at or before the current playback position. Effects persist until the next entry changes them.

Devices are pre-triggered based on their declared latency (e.g. a space heater with 30s latency starts heating 30s before the scene begins).

## Compression

Generated by run-length encoding the dense per-frame timeline: consecutive frames with identical `(wind, water, heat_ambient, heat_radiant)` tuples are collapsed into a single entry. A typical 2-hour film at 0.5fps compresses from ~3600 frames to 50–100 entries.

## Planned extensions

- `wind_direction`: directional metadata for multi-fan spatial effects
- `water_type`: rain vs spray for different mister configurations
- `cold`, `fog`: additional effect channels

Extensions are backwards compatible — playback systems ignore fields they don't support.
